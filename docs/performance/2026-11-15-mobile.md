# Mobile performance repair - 2026-11-15

Baseline: 8f8874f. Viewport 390x844, Chromium, 6x CPU slowdown.
No real study history or sync credentials were used. The review benchmark adds
600 overdue word records and 200 kanji records in disposable browser memory.
External font/icon requests are blocked in the controlled benchmark to isolate
app work. Timings are not measurements of a particular physical phone.

## Causes and changes

- Review due scanned stats once per lesson, resolving each vocab ID through a
  whole-book search. Added a dataset-scoped lookup and a single-pass summary.
  Stats remain live, so grades and merged sync immediately change counts.
- Vocab constructed 1905 topic cards at once. It now constructs 40 at a time,
  automatically loading more on scroll with an explicit button fallback.
  Filtering, totals and drills still use the complete selection. Verified all
  1905 cards can be reached, then chapter filtering still works.
- Offscreen grammar/test/word cards no longer require full layout and paint on
  mobile. No content or study mode was removed.
- Session summaries created thousands of Intl formatters. One formatter now
  handles all dates, with the same IST date semantics.
- Book files start concurrently while ingestion stays in original source order.
  Uncached slow-network load is still bandwidth-sensitive: an uncompressed
  local-server 1.6Mbps simulation took about 41s before and after. This repair
  must not be described as eliminating slow initial downloads. Production
  serves compressed data, unlike that local test.
- Removed mobile route fade-in delay and kept the sync-off badge clear of the vocab title.
- During regression checks, backup create/restore failed on baseline because
  reading-attempt functions lacked imports. Added the missing imports and
  verified snapshot/restore and two-device merging.
- Hide the mobile sync badge while a test is running so it cannot cover Jump.

## Checks

New `scripts/verify-mobile-due-summary.mjs` covers all A/B/Both and lesson filter
combinations against both the existing counter and actual launch queue, live
stats updates, replaced datasets and absence of display writes.

Existing checks passed: daily summary retry/max merge, deferred Gist writes,
two-device merge, backup full round trip, 72 kanji review option combinations,
coverage-aware standalone kanji dedup, 83 grammar patterns/495 drill resolutions,
test navigation/flags/results/weak points, session-size and review-phase rules.

The legacy SRS chapter-filter test cannot start in bare Node because it imports
browser code before defining localStorage; the new isolated summary test and
browser tests cover the changed path instead.

Run the diagnostic browser benchmark from the repository root after installing
Playwright locally: `node scripts/profile-mobile.mjs`. It uses a local server,
disposable Chrome context, synthetic stats and no Gist credentials. Set URL to
the deployed public site for a read-only deployment benchmark. It never grades
cards, starts review sessions or calls sync/account endpoints.
